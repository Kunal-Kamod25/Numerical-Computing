CHAIN 1: GERSHGORIN INHERITANCE CHAIN (TOP-DOWN)
================================================

Matrix
  ├─ PROTECTED DATA:
  │   └─ int rows, cols
  │   └─ mat[][]  (2D matrix)
  │   └─ solution_vec[]
  │
  ├─ METHOD GROUPS:
  │   ├─ Constructors: Matrix(), Matrix(r,c), Matrix(other)
  │   ├─ Operators: +, -, *, /, (), ==
  │   ├─ File I/O: readFromFile(), displayToFile()
  │   ├─ Shape: isSquare(), isSymmetric(), isDiagonal()
  │   ├─ Transforms: transpose(), determinant(), inverse()
  │   └─ ★GERSHGORIN★: gershgorinDisks(), gershgorinRealBounds()
  │
  └─→ Eigenvalues INHERITS ALL ABOVE +
       ├─ WRAPPER METHODS:
       │   └─ getDisks()        { return gershgorinDisks(); }
       │   └─ getRealBounds()   { return gershgorinRealBounds(); }
       │
       └─→ Gershgorin INHERITS ALL ABOVE +
            ├─ CONVENIENCE ALIASES:
            │   └─ disks()       { return getDisks(); }
            │   └─ realBounds()  { return getRealBounds(); }


CHAIN 2: LAGRANGE INHERITANCE CHAIN (TOP-DOWN)
===============================================

Matrix
  ├─ PROTECTED DATA:
  │   ├─ int rows, cols
  │   ├─ mat[][]  (2D matrix - not used for interpolation)
  │   └─ solution_vec[]  (not used for interpolation)
  │
  └─→ Interpolation INHERITS above +
       ├─ NEW PROTECTED DATA:
       │   ├─ std::vector<long double> xData      (x-coordinates)
       │   └─ std::vector<long double> yData      (y-coordinates)
       │
       ├─ CONCRETE METHODS:
       │   ├─ setData(x, y)        { xData=x; yData=y; validate(); }
       │   ├─ pointCount()         { return xData.size(); }
       │   ├─ getX()               { return xData; }
       │   └─ getY()               { return yData; }
       │
       ├─ PURE VIRTUAL (no implementation):
       │   ├─ evaluate(x) = 0
       │   └─ evaluateRange(xMin, xMax, samples) = 0
       │
       └─→ Lagrange INHERITS all above +
            ├─ IMPLEMENTED METHODS (override virtual):
            │   ├─ evaluate(x)        { compute Lagrange polynomial }
            │   └─ evaluateRange(...) { call evaluate many times }

Category G: ★ GERSHGORIN SPECIFIC (KEY For Chain 1) ★
════════════════════════════════════════════════════

25. std::vector<GershgorinDisk> gershgorinDisks() const
    PURPOSE: Compute Gershgorin circles
    RETURNS: Vector of structs {center, radius}
    
    ALGORITHM:
      for i in 0..n-1:
        center_i = a_ii        (diagonal element)
        radius_i = Σ|a_ij|    (sum of absolute values, j≠i)
    
    USAGE IN Chain 1:
       Gershgorin g(3, 3);
       g.readFromFile("matrix.txt");
       auto disks = g.gershgorinDisks();         // Inherited, used by getDisks()
       // Now Eigenvalues wraps it:
       auto disks = g.getDisks();                // Calls gershgorinDisks()
       // Now Gershgorin aliases it:
       auto disks = g.disks();                   // Calls getDisks()
    
    EXAMPLE OUTPUT:
       Disk 0: center = 5.0, radius = 2.5
       Disk 1: center = 8.0, radius = 1.8
       Disk 2: center = 3.0, radius = 0.7

26. std::pair<long double, long double> gershgorinRealBounds() const
    PURPOSE: Find min/max eigenvalue bounds from all disks
    RETURNS: (min_eigenvalue, max_eigenvalue)
    
    ALGORITHM:
      min_bound = min(center_i - radius_i) for all i
      max_bound = max(center_i + radius_i) for all i
    
    USAGE IN Chain 1:
       auto bounds = g.gershgorinRealBounds();         // Inherited
       auto bounds = g.getRealBounds();                // Wraps it
       auto bounds = g.realBounds();                   // Wraps it
    
    EXAMPLE:
       Disk 0: [5.0-2.5, 5.0+2.5] = [2.5, 7.5]
       Disk 1: [8.0-1.8, 8.0+1.8] = [6.2, 9.8]
       Disk 2: [3.0-0.7, 3.0+0.7] = [2.3, 3.7]
       Combined: min = 2.3, max = 9.8
       → Eigenvalues in [2.3, 9.8]

================================================================================
KEY INSIGHTS: WHAT GETS REUSED
================================================================================

EIGENVALUES/GERSHGORIN (Chain 1) REUSES:
=========================================
✓ Data storage: rows, cols, mat[][] - matrix dimensions and elements
✓ I/O: readFromFile(), displayToFile() - load and save matrices
✓ Algorithms: gershgorinDisks(), gershgorinRealBounds() - core eigenvalue analysis
✓ Properties: isDiagonallyDominant(), isSquare() - check matrix conditions
✓ Transforms: transpose(), determinant() - optional matrix operations
✓ Access: operator() - element access [i][j]

WHY INHERITANCE MAKES SENSE:
  - Eigenvalues IS-A Matrix (specializes in eigenvalue analysis)
  - Inherits all matrix operations for matrix manipulation
  - Applies Gershgorin algorithm to inherited matrix data
  - Clean interface: loadMatrix → analyzeEigenvalues → getBounds


INTERPOLATION/LAGRANGE (Chain 2) REUSES:
=========================================
✓ Class structure: Inherits from Matrix (for code organization)
✗ Data storage: Doesn't use mat[][] (uses xData/yData instead)
✗ I/O: Doesn't use readFromFile() (uses setData() instead)
✗ Matrix operations: Doesn't use arithmetic operators
✓ Inheritance principle: Extending base with new methods

WHY INHERITANCE MAKES SENSE:
  - Interpolation IS-A Matrix (extends it with new behavior)
  - Data structure already established in Matrix base
  - Conceptual: Both are numerical data holders
  - Polymorphism: Can treat as Matrix if needed (rarely done)


WHAT WOULD HAPPEN WITHOUT INHERITANCE:
========================================

Option 1: Manual Replication (BAD)
─────────────────────────────────
  class Eigenvalues {
    private: int rows, cols;
             std::vector<...> mat;
             std::vector<...> solution_vec;
    public: readFromFile(...) { ... }  // DUPLICATED CODE
            displayToFile(...) { ... }  // DUPLICATED CODE
            ... all Matrix methods again ...
  }
  
  Problem: Code duplication, maintenance nightmare

Option 2: Composition (ALTERNATIVE)
────────────────────────────────────
  class Eigenvalues {
    private: Matrix m;  // Contains a Matrix
    public: auto disks() { return m.gershgorinDisks(); }
  }
  
  Problem: Cannot use Eigenvalues AS A Matrix (no polymorphism)
           Requires forwarding every method manually

Option 3: Inheritance (ACTUAL - BEST)
─────────────────────────────────────
  class Eigenvalues : public Matrix { ... }
  
  Benefits: Code reuse, IS-A semantics, can pass Eigenvalues where Matrix expected
           Clean, maintainable, follows OOP principles
